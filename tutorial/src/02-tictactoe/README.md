# Chapter 2: 틱택토 — 상태, 가치, 그리고 시간차 학습

## Phase 1의 한계: 왜 MDP가 필요한가?

1장에서 우리는 슬롯머신 문제(Multi-Armed Bandit)를 풀었다. Bandit에서는 **상태가 하나**였다.
어떤 버튼을 눌러도 세상은 그대로였고, 과거의 선택이 미래 선택지에 영향을 주지 않았다.

틱택토는 본질적으로 다르다. **행동이 상태를 바꾼다.** 한 수를 두면 보드가 달라지고,
다음에 선택할 수 있는 자리도 달라진다. 게임이 끝날 때까지 이 과정이 반복된다.

이것이 **MDP(Markov Decision Process)**의 핵심이다:

| 개념 | Bandit | 틱택토 |
|------|--------|--------|
| 상태 | 단 하나 (항상 같은 상황) | 수천 개 (보드 배치) |
| 행동의 영향 | 없음 | 상태 전이 |
| 보상 시점 | 즉각적 | 게임 종료 시 |
| 최적 전략 | 최고 기댓값 arm 선택 | 미래 상태까지 고려 |

Bandit에서는 `incrementalMean`으로 평균 보상만 추적하면 됐다.
틱택토에서는 **"이 보드 배치에서 이길 확률이 얼마인가"**를 추적해야 한다 — 이것이 **가치 함수**다.

## MDP 핵심 개념

**상태 (State):** 현재 보드 배치 (9칸 × {빈칸, X, O} = 최대 19,683가지, 실제 도달 가능 ~5,478가지)

**행동 (Action):** 빈 칸에 돌 놓기 (최대 9개, 게임 진행에 따라 감소)

**전이 (Transition):** `applyMove board player move` → 새 보드

**보상 (Reward):** 게임 종료 시에만 발생 (승: 1.0, 패: 0.0, 무: 0.5)

**가치 함수 (Value Function):** `V(s)` = 상태 s에서 X가 이길 확률

## TD(0) 학습: 시간차 업데이트

**TD Learning (Temporal Difference Learning)**은 실제 게임 플레이를 통해 가치 함수를 업데이트한다.
몬테카를로 방법처럼 게임이 끝날 때까지 기다리지 않고, **매 수마다 즉각 업데이트**한다.

업데이트 공식:

```
V(s) ← V(s) + α × (V(s') - V(s))
```

- `V(s)`: 현재 상태의 가치 추정치
- `V(s')`: 다음 상태의 가치 추정치
- `α (alpha)`: 학습률 (0.1 ~ 0.3)
- `V(s') - V(s)`: TD 오차 (예측이 얼마나 틀렸나)

직관: **다음 상태가 현재보다 좋아 보이면 현재 상태 가치를 올린다**. 나빠 보이면 내린다.

  ✓ 플레이어는 교대한다: X 이후 O 차례

  ✓ TD 에이전트가 100k 자가 대국 후 랜덤 상대 승률 > 90%

## Phase 3 예고: 왜 상태 공간이 문제인가?

틱택토의 상태 수는 ~5,478개 — `Map<Board, float>` 하나에 충분히 들어간다.

하지만 Connect Four는? 6×7 보드, 최대 42수. 가능한 상태 수는 4조(4×10¹²)를 넘는다.
이 크기의 가치 테이블은 메모리에 들어가지 않는다.

3장에서는 이 문제를 두 가지 방향으로 접근한다:

1. **Q-Learning + 특징 추출**: 상태 전체 대신 보드의 특징(연속 돌 수 등)을 사용
2. **Minimax Alpha-Beta**: 가치 함수 없이 게임 트리 탐색으로 최선 수 계산
